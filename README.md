# Ultima Memento for CubeCoders AMP

An AMP *generic module* template for [Ultima Memento](https://github.com/Jascen/ultima-memento), the
single-player / small-group Ultima Online shard based on Ruins & Riches (RunUO).

- Pick **Ultima Memento** when creating an instance, click **Update**, click **Start**.
- Runs on **Windows** (.NET Framework, compiler built into Windows) and **Linux** (Mono).
- Every setting in `World/Info/Scripts/Settings.cs` is editable on the AMP Configuration pages.
  Only the values that differ from the defaults are written to
  `World/Info/Scripts/Settings.override.cs`, regenerated before every start.
- Installs from the latest release, a specific release, or a GitHub branch/tag/commit, and
  compiles the server on the host.

## 1. Add the template to AMP

AMP loads templates from GitHub repositories.

1. Push the contents of this folder to a GitHub repository, for example `yourname/amp-ultima-memento`.
   The `*.kvp` and `*.json` files must be in the repository root.
2. In AMP open the main (ADS) instance, then **Configuration → Instance Deployment**.
3. Add `yourname/amp-ultima-memento:main` to **Configuration Repositories**
   (keep `CubeCoders/AMPTemplates:main` in the list), then click **Fetch latest**.
4. **Create Instance** → choose **Ultima Memento** from the application list.

## 2. First start

1. On the new instance open **Configuration → Memento Server → Administration** and set
   **Owner Account Password**. The starting world ships with an Owner account `Admin` whose
   password is `password`, so set this before anyone else can connect.
2. Click **Update**. This downloads the release (~130 MB), installs it into `ultima-memento/World`
   and compiles the server. On Linux it compiles `WorldLinux.exe` with Mono.
3. Click **Start**. The first start compiles all game scripts, which takes a few minutes. The instance
   shows *Running* when the console prints `[AMP] Server started`.
4. Log in with your UO client as `Admin` and run `[BuildWorld` once (the upstream fresh-install step).
5. Open TCP port **2593** in your firewall/router (or whatever you set under the instance's ports).

Client files and the player guide are linked from the upstream
[release notes](https://github.com/Jascen/ultima-memento/releases/latest).

## How the settings work

Settings are grouped like the sections of `Settings.cs`:

| AMP category | Contents |
| --- | --- |
| Memento Server → Install & Updates | where to install from, how to build, update behaviour |
| Memento Server → Administration | owner account, override management, extra arguments |
| Memento Server → Server Options | section 001 (save interval, server name, address, ...) |
| Memento Gameplay → ... | sections 002–012 (game, players, quests, skills, crafting, monsters, merchants, homes, pets, towns) |

Each description is the upstream comment from `Settings.cs`, followed by the default and the
setting's name in brackets.

Before every start AMP writes your values to `ultima-memento/amp/settings.kvp`. The helper
program (`MementoAmp`) then compares each value with the default in the **installed**
`Settings.cs` and writes only the differences to `Settings.override.cs`:

```csharp
// GENERATED BY THE CUBECODERS AMP "ULTIMA MEMENTO" TEMPLATE - DO NOT EDIT
namespace Server
{
	public static class SettingOverrides
	{
		[CallPriority( -1000000 )]
		public static void Configure()
		{
			MySettings.S_ServerName = "My Shard";
			MySettings.S_Port = 2600;
		}
	}
}
```

Details:

- The overrides are applied in the `Configure` phase, before any `Initialize`. The stock
  `Initialize()` hook runs too late for settings read at startup: the listening port
  (`S_Port`), `S_Address` and `S_AutoDetect` are read into static fields as the server starts.
- `S_Port` is not a text box. It follows the instance's **Game Port**, so AMP's port management
  and firewall rules stay in sync.
- The file is only rewritten when its content changes. The server reuses its compiled script
  cache when nothing changed, so a restart doesn't trigger a full recompile.
- If upstream changes a default that you never touched in AMP, the new upstream default is used.
  It is not pinned to the value the template was generated with.
- An AMP value whose setting no longer exists upstream is skipped with a warning, so the scripts
  still compile. An invalid value (for example `5.5` for a whole-number setting) stops the start
  with a message naming the setting.
- Want to edit `Settings.override.cs` by hand? Turn off **Manage Settings.override.cs**. AMP then
  leaves that file alone, and the gameplay settings on these pages have no effect.
- Put your own scripts in another file under `World/Info/Scripts`, not in `Settings.override.cs`.

## Install sources and updates

| Install Source | What Update does |
| --- | --- |
| Latest official release (default) | downloads `Ultima-Memento-Server.zip` from the latest GitHub release |
| A specific release | same, for the tag in **Release Tag** (e.g. `2.5.0`) |
| Latest release + source code | latest release (for the map data files), then the code of **Branch, Tag or Commit** from GitHub on top |

The release zip is always needed: only it contains the map data (`World/Data/Files/*.mul`); the
git repository does not.

**Server Core (World.exe)**: *Compile on this machine* (default) builds `World.exe` with the C#
compiler that ships with Windows (`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`), like the
upstream `compile-world-win.bat`. *Use the World.exe included in the release* skips that on
Windows. Linux always compiles `WorldLinux.exe` with `mcs` (`-d:MONO`), like
`compile-world-linux.sh`.

What an update keeps:

| Path | On update |
| --- | --- |
| `World/Saves` | copied only on a fresh install, never replaced |
| `World/Backups` | never touched |
| `World/Info/Scripts/Settings.override.cs` | never replaced |
| `World/Info/Scripts/Settings.cs`, `*.csproj` | always updated (must match the code) |
| other `World/Info` files (news, rules, articles, spawns, `Merchant.cs`) | kept, only new files added; set **Info Folder on Update** to *Replace* to take the new versions |
| `World/Source` | replaced by the new code, so files deleted upstream don't linger and break the compile |
| `World/Data/Data.bin` (script cache) | deleted, so the next start recompiles the scripts |

Stop the server before updating, and take an AMP backup first if your world matters to you.

## The AMP console

The template adds a small script, `World/Info/Scripts/AMP/AmpBridge.cs`, installed before each
start. It lets the AMP console control the server:

| Command | Effect |
| --- | --- |
| `save` | save the world now |
| `shutdown` | save, then stop (AMP's **Stop** button sends this) |
| `shutdown nosave` | stop without saving |
| `broadcast <text>` | message every online player |
| `online` | list online players |
| `help` | list the commands |

It also:

- prints the lines AMP uses for "server ready" and for the player list (join / leave)
- applies **Owner Account Password**, and warns while `Admin` still has the default password
- exits after a crash instead of starting a second, invisible copy of the server. CrashGuard still
  writes its report and a backup of the saves. Turn on AMP's restart-on-crash option if you want
  automatic restarts.
- replaces the in-game `[Restart` command with a message to use AMP's Restart button, because a
  restarted process would run outside AMP's control

AMP backups send `save` first (the template's quiesce command), so a backup contains a fresh save.

`S_EnableConsole` is not needed under AMP. If you turn it on, the game's own console takes over;
it also understands `save` and `shutdown`, but its authors warn it may crash the server.

## Linux

- In a container (the default when AMP uses Docker) the image `cubecoders/ampbase:mono-latest`
  already includes Mono with the compiler.
- Without a container, install Mono on the host first, for example `sudo apt install mono-complete`
  (the [Mono project packages](https://www.mono-project.com/download/stable/) if your distro has none).
- The server loads zlib as `libz`, which plain Debian/Ubuntu only provides with the `-dev` package.
  The update writes `WorldLinux.exe.config` with a Mono mapping to `libz.so.1`, so nothing extra is
  needed.

## Files on the instance

```
ultima-memento/
  World/                      the server (Saves, Backups, Info, Source, Data, World.exe / WorldLinux.exe)
  amp/
    MementoAmp.cs / .exe      helper: install/update and Settings.override.cs generation
    AmpBridge.cs              copied into World/Info/Scripts/AMP/ when it changes
    settings.kvp              your AMP values, written before every start
    template-defaults.kvp     the defaults this template was generated with
    installed.txt             what the last update installed
```

## Maintaining the template

The JSON files are generated. When upstream adds, removes or renames settings, regenerate them:

```bash
python tools/build.py
```

Then commit and push, and click **Fetch latest** in AMP. `--ref 2.5.0` reads `Settings.cs` from a
tag or branch, and `--settings path/to/Settings.cs` reads a local file. The script needs only Python 3.

- `src/MementoAmp.cs` and `src/AmpBridge.cs` are embedded into the stages by `build.py`. AMP treats
  double curly braces as placeholders, so these files must never contain two `{` or two `}` next to
  each other; `build.py` refuses to build if they do.
- Bump `CONFIG_VERSION` in `build.py` when you change the template so AMP notices.
- Friendlier display names live in `DISPLAY_NAMES` in `build.py`. New upstream settings get a name
  generated from the field name.

## Troubleshooting

- **"The server is not installed yet"**: click **Update** first.
- **The start fails with "Invalid value(s) in the AMP settings"**: the message names the setting;
  fix it on the Configuration page.
- **Script compile errors after an update**: if you set **Install Source** to source code, that
  branch may be broken upstream. Switch back to the latest release and update again.
- **Port changes**: change the Game Port in the instance's network/port settings, not in a text box.
- **No `[AMP]` lines in the console**: check that `World/Info/Scripts/AMP/AmpBridge.cs` exists.
  The pre-start stage installs it.
